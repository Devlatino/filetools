A 5 MB GIF and a 500 KB MP4 can show the same clip. That’s the main reason to convert GIFs to MP4: much smaller files, better quality, and the same “auto-playing loop” behavior on the web. Here’s why it works and how to do it for free.

## The problem: GIF is huge

GIF uses a simple, old compression. Every frame is stored with limited color and little compression. **MP4 (H.264)** uses modern video compression: keyframes plus differences between frames, so the same animation often becomes **around 10x smaller** as MP4. You save bandwidth and load time without losing (and often improving) visual quality.

## How H.264 beats GIF (in simple terms)

- **GIF** — Frame-by-frame; each frame is like a small image. Little redundancy is removed.
- **MP4 (H.264)** — Only keyframes are full images; other frames store only what changed. Result: much smaller files and support for more colors and smoother playback.

So for the same duration and resolution, MP4 usually wins on size and look.

## Where to use MP4 instead of GIF

- **Twitter / X** — Prefers video; MP4 often shows as an inline, looping clip.
- **Discord** — Supports MP4; smaller uploads and faster loading.
- **Websites** — One line of HTML and the clip autoplays and loops like a GIF.
- **Email** — Support varies, but many clients can show small MP4s.

Whenever the platform supports video, prefer MP4 over GIF.

## Autoplay loop MP4 like a GIF in HTML

Use the same pattern as for GIF-style clips:

```html
<video autoplay loop muted playsinline>
  <source src="animation.mp4" type="video/mp4" />
</video>
```

- **autoplay** — Starts without user click.
- **loop** — Repeats like a GIF.
- **muted** — Required for autoplay in most browsers.
- **playsinline** — Prevents fullscreen on mobile.

Browser support is universal for this pattern.
